# OrderHub — учёт заказов интернет-магазина

Консольное приложение на C# (.NET 10). Это итоговый проект по контрольным точкам **КТ 31 – КТ 39** «Коллекции, LINQ, перечислители и итераторы в C#».

Проект развивается поэтапно в одном репозитории: каждая тема добавляет в OrderHub свой сценарий, от очереди заказов на `Queue<T>` до собственной коллекции с поддержкой `foreach`.

# Ответы на вопросы

## 1. Чем `Queue<T>` отличается от `Stack<T>` и когда применяется каждый?

- `Queue<T>` работает по принципу **FIFO** (первым пришёл, первым вышел). `Enqueue` добавляет в конец, `Dequeue` забирает из начала. Применяется для очередей заказов, задач и сообщений.
- `Stack<T>` работает по принципу **LIFO** (последним пришёл, первым вышел). `Push` добавляет, `Pop` забирает последний элемент. Применяется для отмены действий (undo), истории переходов и разбора скобок.

## 2. Зачем сохранять узел, возвращённый `AddLast`, вместо повторного поиска через `Find`?

- `AddLast` возвращает готовый `LinkedListNode<T>`, и доступ к нему занимает O(1). `Find` перебирает список за O(n).
- `Find` ищет по значению, поэтому при дубликатах может вернуть не тот узел.
- Сохранённый узел сразу передаётся в `AddAfter` или `AddBefore`, и проверка на `null` не нужна.

## 3. Почему чтение отсутствующего ключа через индексатор даёт исключение и как этого избежать?

Индексатор `d[key]` обязан вернуть значение. Для отсутствующего ключа вернуть нечего, и он бросает `KeyNotFoundException`.

Как избежать:

- `TryGetValue(key, out var v)` проверяет наличие и читает значение за один вызов (предпочтительный способ).
- `ContainsKey` перед чтением. Тогда поисков получается два.

## 4. В чём разница между `IComparable<T>` и `IComparer<T>`? Что будет при `Sort()` для типа без обоих интерфейсов?

| | `IComparable<T>` | `IComparer<T>` |
|---|---|---|
| Где реализуется | в самом типе | в отдельном классе |
| Метод | `CompareTo(other)` | `Compare(a, b)` |
| Что задаёт | один «естественный» порядок | любые альтернативные порядки |
| Нужно менять тип | да | нет |

Если у типа нет ни того, ни другого, `Sort()` без аргументов бросит `InvalidOperationException` (внутри будет `ArgumentException`: не удалось сравнить два элемента). Исправить можно, передав `IComparer<T>` или лямбду `Comparison<T>`.

## 5. Что такое отложенное (ленивое) выполнение LINQ-запроса и когда происходит обход?

`Where`, `Select`, `OrderBy` и подобные методы только **строят запрос** и ничего не вычисляют. Обход источника происходит при потреблении результата:

- `foreach`
- `ToList()`, `ToArray()`
- `Count()`, `First()`, `Sum()` и другие агрегаты

Запрос выполняется заново при каждом перечислении и видит текущее состояние источника.

## 6. Чем `IGrouping<TKey, TElement>` отличается от обычной коллекции и какие операции к нему применимы?

- Это `IEnumerable<TElement>` с дополнительным свойством `Key` (ключ группы).
- Применимы все операторы LINQ: `Count`, `Sum`, `Average`, `Min`, `Max`, `Where`, `Select`, `OrderBy`, `First` и другие.
- Группа только для чтения: у неё нет `Add` и индексатора.

## 7. Как работает `Join` и что будет, если у одного клиента несколько заказов?

- `Join(second, key1, key2, resultSelector)` сопоставляет элементы двух коллекций по равенству ключей (внутри строится хеш-таблица) и выдаёт **одну строку на каждую совпавшую пару**.
- Если у клиента три заказа, будет три строки с одним и тем же клиентом. Поэтому после `Join` обычно идут `GroupBy` и `Sum`.
- Элементы без пары в результат не попадают (inner join).

## 8. Почему бесконечный итератор не вешает программу, а `Take(N)` ограничивает его работу?

- Код метода с `yield return` выполняется лениво. Он доходит до очередного `yield return`, отдаёт элемент и **приостанавливается**, пока потребитель не запросит следующий.
- `Take(N)` запрашивает ровно N элементов и перестаёт вызывать `MoveNext`, поэтому `while (true)` не доходит до конца.
- Зависнут только `ToList()`, `Count()` и подобные вызовы без `Take`: они пытаются обойти всю бесконечную последовательность.

## 9. Зачем нужна явная реализация `IEnumerator IEnumerable.GetEnumerator()` в собственной коллекции?

- `IEnumerable<T>` наследует неуниверсальный `IEnumerable`, поэтому класс обязан реализовать **оба** метода.
- Они различаются только возвращаемым типом, и в одном классе два одноимённых метода без параметров объявить нельзя. Неуниверсальный метод реализуют явно, через имя интерфейса.
- Он просто вызывает универсальный:

```csharp
IEnumerator IEnumerable.GetEnumerator() => GetEnumerator();
```

Без него класс не скомпилируется.

## 10. Как в кольцевом буфере определить индекс самого старого хранящегося элемента?

```csharp
int oldest = (next - size + capacity) % capacity;
```

Здесь `next` — позиция следующей записи, `size` — число хранимых элементов.

- Пока буфер не заполнен, `oldest = 0`.
- После заполнения `size = capacity`, и `oldest = next`: следующая запись затрёт именно самый старый элемент.

Пример для ёмкости 3 и добавленных 1…5: `next = 5 % 3 = 2`, `oldest = (2 − 3 + 3) % 3 = 2`. В `buffer[2]` лежит «3», значит, обход даст 3, 4, 5.

## 11. Чем готовый проект с девятью этапами лучше девяти отдельных заданий?

- Код **накапливается и развивается**, как в реальной разработке. Новые возможности встраиваются в уже работающую систему.
- Коллекции можно **сравнивать на одной предметной области** (`List` и `LinkedList`, `IComparable` и `IComparer`).
- Темы **связаны между собой**: склад (этап 3) и товары (этап 4) используются в LINQ-отчётах (этапы 5–7), а итераторы этапов 8–9 продолжают тему перечисления.
- Появляется практика **Git**: ветка на этап, Pull Request, линейная история, README.
- На выходе **одно готовое приложение** для демонстрации и защиты, а не набор разрозненных консольных примеров.
